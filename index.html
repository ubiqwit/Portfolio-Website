Approach

On building with LLMs

LLMs have changed what writing software means. Producing code is no longer the hard part. The hard part is deciding what to build, how it should be structured, and whether the result is any good.

I think that’s where a developer’s focus belongs now: architecture, planning and design, and learning to work with LLMs in a way that produces high-quality code rather than unmanageable slop.

  • Architect first

    Decide the structure, the data model and the boundaries before any code is generated.

  • Plan and specify

    A clear plan and a precise specification are what make LLM output predictable and reviewable.

  • Own the output

    Generated code still needs an owner. Tests, review and a coherent design are what keep it maintainable.
